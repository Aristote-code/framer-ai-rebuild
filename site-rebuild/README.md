# framer-ai rebuild — 13 routes

A clean, editable rebuild of 13 pages from `framer-ai.com`, generated by
[`extract-site`](../README.md) and composed into one navigable site.

**This is a copy of someone else's site**, produced for development and
fidelity comparison. It ships `noindex`/`nofollow` (meta tag, `robots.txt`, and
an `X-Robots-Tag` header via `netlify.toml`) so it is never indexed as though it
were the original. Don't remove those.

## Run it

```bash
bun install
bun run dev     # http://localhost:5173
bun run build   # -> dist/
```

## Routes

`/` · `/academy` · `/agents` · `/cms` · `/collaborate` · `/design` ·
`/enterprise` · `/hosting` · `/performance` · `/publish` · `/seo` ·
`/solutions/designers` · `/stories`

## Layout

- `src/pages/<slug>/` — one lazily-loaded route each: `page.tsx`, `sections/`,
  `content/`, `data/`, and its own CSS. Editing a section file hot-reloads.
- `src/App.tsx` — a small history router that intercepts internal links.
- `src/NavDropdowns.tsx` — the hover mega-menus. Framer mounts these on hover so
  they don't exist in a static capture; they were captured separately by
  `extract-site capture-nav` and are shared across every route.
- `public/` — localized images, videos and fonts.

## Known limits

- **Desktop only (1440px).** No responsive rules are generated; at narrow
  widths you get the desktop layout clipped.
- Continuously-animating components (the `/stories` carousel, `/hosting`
  counters, `/publish` highlight) sit at whatever phase they were captured in.
- Hover transitions use a 0.2s default — Framer's real timing is JS-driven and
  isn't visible to the capture.
